# Where documentation goes

Each audience has its own file. When you add or change documentation, put it where its reader looks for it.

- **`README.md` is for users.** It explains what Filey is and does, the requirements, how to install, update and set it up,
  the features and settings, known limitations and troubleshooting. Keep it free of anything only a contributor needs.
- **`CONTRIBUTING.md` is for contributors and maintainers.** Everything about working on Filey belongs here: tech stack,
  code layout, setting up, running and testing, building a DMG, the pull-request workflow and releases.
- **`SECURITY.md` is for security and privacy.** Reporting vulnerabilities, scope, the Privacy section (what leaves the Mac,
  where data and the API key are stored) and security-related limitations.
- **`LICENSE`** is the MIT text and stays unchanged. **`THIRD_PARTY_LICENSES.md`** is generated by `npm run licenses`; do not
  edit it by hand. Do not restate license text in the README.
- **`docs/arc42.md`** holds requirements and design decisions (see `CLAUDE.md` for the approval rule).
- There is no code of conduct and no changelog file for now.

Link between these files instead of copying text. If a README section starts to explain how to build, test or release
Filey, move it to `CONTRIBUTING.md` and link to it.
